# NECESIDADES REALES

## 1. Cobertura

Quiero alcanzar una cobertura suficientemente alta para que la probabilidad de perder una oportunidad relevante sea mínima.

Fuentes objetivo:

- Idealista
- Fotocasa
- Yaencontre
- Pisos.com
- inmobiliarias locales
- agencias pequeñas

## 2. Automatización

Quiero dejar de revisar manualmente decenas de webs.

La aplicación debe automatizar todo lo razonablemente posible sin generar un sistema complejo o difícil de mantener.

## 3. Novedades

Quiero detectar:

- viviendas nuevas
- bajadas de precio
- viviendas desaparecidas
- oportunidades interesantes

## 4. Colaboración

La vivienda es para mi suegra.

Yo la estoy ayudando en la búsqueda.

Necesitamos poder:

- guardar favoritos
- guardar comentarios
- comparar opiniones

## 5. Multidispositivo

La aplicación debe poder utilizarse desde:

- ordenador
- móvil

## 6. Coste

No quiero depender de múltiples servicios de pago.

Actualmente ya pago Cursor.

# MODELO DE DATOS FUNDAMENTAL

La entidad principal NO son los anuncios.

# CAPTURA DE VIVIENDAS

La incorporación de viviendas debe ser extremadamente sencilla.

Flujo ideal:

1. Encontrar vivienda.
2. Copiar URL.
3. Abrir Radar.
4. Pulsar "Añadir vivienda".
5. Pegar URL.
6. Importar.

Fuentes típicas:

- Idealista
- Fotocasa
- Web inmobiliaria

El tiempo de incorporación debería ser inferior a 30 segundos.

La facilidad de uso tiene prioridad sobre la perfección de los datos.

# DETECCIÓN DE DUPLICADOS

Una vivienda puede aparecer en múltiples portales.

La aplicación debe intentar detectar duplicados mediante:

- dirección
- coordenadas
- superficie
- precio
- fotografías
- descripción
- referencias

Si se detectan duplicados:

- consolidar en una única vivienda
- conservar todas las URLs
- conservar todas las fuentes

El objetivo es gestionar viviendas, no anuncios.

# DECISIÓN FINAL

Antes de proponer cualquier arquitectura responde:

1. ¿Construirías realmente este sistema de esta manera?

2. Si no lo harías:
   - explica por qué
   - qué simplificarías
   - qué eliminarías
   - qué retrasarías
   - qué cambiarías

3. ¿Cuál sería el MVP más pequeño posible que ya aporte valor real?

4. ¿Cuál sería la arquitectura mínima viable para conseguirlo?

5. ¿Qué partes del problema parecen importantes pero aportan poco valor al usuario?

6. ¿Qué funcionalidades eliminarías o retrasarías para acelerar la entrega de valor?

7. ¿Qué harías diferente si este fuera tu proyecto personal?

Quiero la mejor solución real, no la solución más impresionante técnicamente.
